## 一、 为什么在大陆不能访问 Google / YouTube？

这并非简单的“拔网线”，而是一套由 GFW（Great Firewall）主导的动态流量审计系统。它主要通过以下三种技术层层拦截：

* **DNS 污染**：当你请求 `google.com` 时，运营商的 DNS 服务器会故意返回一个错误的 IP 地址，让你在第一步就“走错路”。
* **SNI 阻断**：即使你通过修改 Hosts 知道了正确 IP，但在 TLS 握手阶段，GFW 会嗅探到你发送的明文 **SNI（服务器名称指示）**。一旦匹配到黑名单（如 `youtube.com`），会直接向双方发送 RST 包强行重置（Reset）连接。
* **DPI 深度包检测**：通过机器学习和统计学特征，GFW 可以识别出流量的“体态”。如果发现一段流量虽然加密，但其握手包大小、时序行为符合代理协议特征，就会实施精准阻断或 QoS（限速丢包）。

## 二、 协议进化论：从“翻墙”到“伪装”

传统的加密在现代 DPI 面前形同裸奔，促使代理协议完成了三次迭代：

### 1. 经典代理时代（特征对抗）

* **Shadowsocks (SS)**：早期的翻墙鼻祖，通过预共享密钥对流量进行对称加密。其致命弱点是加密后的数据流过于“杂乱无章”，具有极高的熵值，在现代 GFW 看来属于典型的异常特征，极易被精准封锁。
* **Trojan**：放弃对抗，选择顺从。将代理流量直接伪装成最常见的 **HTTPS 网站流量**。只要网站证书合法，GFW 很难在不解密的情况下区分它是正常浏览还是代理。

### 2. 多态与定制时代（混淆演进）

* **VMess / VLess**：V2Ray 生态的核心协议。**VMess** 带有复杂的身份验证和时间戳（对时钟要求严苛）；而 **VLess** 进行了极致瘦身，去掉了繁琐的轻量验证，完全依赖下层传输安全（TLS），性能更强、延迟更低。
* **Hysteria2**：基于 **UDP (QUIC 协议)** 的魔改方案。它不追求隐蔽，而是追求“速度”。在丢包严重的恶劣网络环境下，它通过主动拥塞控制算法强行榨干带宽，是高延迟、高丢包线路的救星。
* **AnyTLS**：专注于打破 TLS 的统计学规律。通过动态调整 TLS 数据包的 **Padding（填充长度）** 和多路复用，让流量在行为上不符合任何已知的代理特征。

### 3. 传输层的高阶魔改

* **WSS (WebSocket + TLS)**：将代理挂载在 WebSocket 协议上，允许你将流量托管给 **Cloudflare 等 CDN**。即使你的 VPS IP 被封，流量也可以通过 CDN 节点安全转发，是极佳的“IP 逃生舱”。
* **REALITY**：目前抗封锁的天花板。它彻底抛弃了“自建证书”的做法，直接**“偷取”**公网合法网站（如 `dl.google.com`）的 TLS 证书和握手特征。GFW 发起主动探测时，看到的是完美的谷歌官方回复，实现无解伪装。

## 三、 全平台客户端图鉴

协议需要客户端来落地。根据操作系统和内核生态，主流客户端分为两大派系：

### 1. 桌面端（Windows / macOS）

* **v2rayN**：Windows 平台的经典老牌客户端。界面传统，但对 Xray/V2Ray 内核更新支持最快，适合喜欢微调核心参数的技术人员。
* **Clash 系列 (如 Clash Verge / Clash Nyapasu)**：凭借强大的 **Rule-based（基于规则的分流）** 体系风靡全平台。支持通过 YAML 配置文件实现极度精细的国内直连、海外代理、广告过滤。

### 2. 移动端与全能新星（iOS / Android）

* **v2rayNG**：Android 平台上的 V2Ray 官方客户端，简洁纯粹，专注于底层协议的稳定连接。
* **Shadowrocket（小火箭）**：iOS 独占的统治级应用。更新频繁，率先支持 REALITY 等新协议，且规则分流功能极其强大。
* **Hiddify**：基于 **sing-box 内核** 的新一代全平台黑马。界面现代，完美兼容 AnyTLS、Hysteria2 等最新协议，且配置极为傻瓜化。

## 四、 局域网边缘层：全家出海的物理方案

当家里有电视、游戏机或不支持安装客户端的智能设备时，需要在局域网层面做“透明代理”：

* **方案 A：路由器配置代理（软路由/硬路由刷机）**
    * 在路由器上刷入 OpenWrt 固件，部署 **OpenClash** 或 **PassWall**。
    * **优势**：在网关层面进行流量分流，家里所有设备连接 WiFi 即可自动科学上网，完全无感。
* **方案 B：旧手机做代理（低成本网关）**
    * 将一台闲置的安卓手机安装 `v2rayNG`，在设置中开启 **“允许局域网连接” (Allow LAN)**。
    * 将其他设备（如 Mac 或电视）的系统网络代理（Proxy）指向这台手机的局域网 IP 和对应端口，一个零成本的拓扑网关便诞生了。

## 五、 高阶进化：现代虚拟组网与服务暴露

当你拥有了多台物理设备（家里的 NAS、海外的 VPS、手头的 Mac），你需要把它们揉成一个真正的“大局域网”：

### 1. 内网服务暴露（点对点穿透）

* **frp**：经典的开源内网穿透工具。需要一台拥有公网 IP 的服务器作为中转，将你家里的本地端口映射到公网。
* **Cloudflare Tunnel**：安全级别更高。不需要你有公网 IP，本地直接与 Cloudflare 边缘节点建立加密隧道。你可以把家里的私有 AI 模型或 Web 服务安全地暴露给外网，且自带 WAF 防护。

### 2. 虚拟局域网（SD-WAN 网格）

* **Tailscale / ZeroTier**：基于全网格（Mesh）架构的虚拟局域网工具。**Tailscale 基于 WireGuard 协议**，极其擅长在复杂的 NAT 环境下进行 **P2P 打洞直连**。通过它们，你的 Mac 和远在异地的服务器会获得同一个虚拟内网 IP，如同在一个房间里一样互访。

### 3. 站点互联（企业级骨干）

* **WireGuard / IPSec VPN**：当需要将“整个 A 地的局域网”与“整个 B 地的局域网”进行物理打通时，使用 **WireGuard** 建立路由器级别的隧道。它在内核层运行，效率极高，是分布式办公和多中心数据同步的基础设施。
